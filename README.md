# دفتر خاطرات و تولد | DIARY

دفتر خاطرات روزانه، دفترچهٔ تولدها و یادداشت — Kotlin + Jetpack Compose + Material 3، با **تقویم شمسی واقعی**، RTL کامل، اعداد فارسی و فونت وزیرمتن.

> یک روز، یک صفحه.

اپ روی زیرساخت «روزی» ساخته شده (تقویم جلالی، دیزاین‌سیستم، Room، یادآوری، بکاپ) ولی محصولی مستقل است: لیست کار ندارد و اسکیمای دیتابیسش از نسخهٔ ۱ شروع می‌شود. این برنچ فقط شامل همین اپ است.

---

## ۱. اجرای پروژه

```bash
./gradlew :app:assembleDebug        # خروجی دیباگ
./gradlew :app:assembleRelease      # خروجی ریلیز (APK)
./gradlew :app:bundleRelease        # خروجی AAB برای فروشگاه‌ها
./gradlew :app:testDebugUnitTest    # تست‌های واحد (تقویم شمسی)
```

خروجی‌ها:

| فایل | مسیر |
|---|---|
| APK | `app/build/outputs/apk/release/app-release.apk` |
| AAB | `app/build/outputs/bundle/release/app-release.aab` |

نیازمندی‌ها: JDK 17، Android SDK 35 (AGP 8.7.3، Kotlin 2.0.21، Compose BOM 2024.12).

> **توجه:** محیط سندباکسِ توسعه به مخازن Google Maven / Gradle دسترسی نداشت، بنابراین بیلد نهایی باید روی ماشین شما یا GitHub Actions اجرا شود. فایل ورک‌فلوی آماده در `ci/diary-android.yml` قرار دارد — کافی است آن را در `.github/workflows/` قرار دهید تا تست، لینت، APK و AAB خودکار ساخته شوند (توکن ربات اجازهٔ ساخت فایل workflow را نداشت).
>
> منطق تاریخ و کل سورس کاتلین به‌صورت محلی با کامپایلر Kotlin 2.1.21 بررسی شده و **بدون خطا** است؛ تست‌های تقویم شمسی روی ۹۱٬۳۱۱ روز (۱۹۰۰ تا ۲۱۵۰) اجرا و **همگی پاس** شده‌اند.

### پیش‌نمایش طراحی
`preview/index.html` یک پیش‌نمایش زندهٔ HTML از هویت بصری اپ است (همان توکن‌های رنگ، فونت، تقویم شمسی و اعداد فارسی) که بدون نیاز به اندروید استودیو در مرورگر باز می‌شود.

## ۲. تغییر Application ID و نام اپ

هر دو مقدار پارامتریک هستند و بدون دست‌زدن به سورس قابل تغییرند:

```bash
./gradlew :app:assembleRelease \
  -PapplicationId=com.yourcompany.diary \
  -PappName="خاطرات"
```

یا به‌صورت دائمی در `app/build.gradle.kts` مقادیر پیش‌فرض `diaryApplicationId` و `diaryAppName` را عوض کنید.
نام نمایشی لانچر از `res/values/strings.xml` (فارسی) و `res/values-en/strings.xml` (انگلیسی) خوانده می‌شود.

## ۳. امضای APK برای انتشار (کافه‌بازار / مایکت)

```bash
keytool -genkey -v -keystore diary.jks -keyalg RSA \
  -keysize 2048 -validity 10000 -alias diary
```

سپس فایل `keystore.properties` را بسازید:

```properties
storeFile=diary.jks
storePassword=******
keyAlias=diary
keyPassword=******
```

این فایل در `.gitignore` است و هرگز کامیت نمی‌شود. با وجود آن، `assembleRelease` به‌صورت خودکار خروجی امضاشده می‌دهد.

## ۴. قابلیت‌ها

**خاطرهٔ روزانه** — هر روز یک صفحه. تاریخ کلید یکتای رکورد است، پس باز کردن دوبارهٔ یک روز همان صفحه را ویرایش می‌کند و هرگز صفحهٔ دوم نمی‌سازد. صفحه‌ای که بدون عنوان، متن و عکس ذخیره شود پاک می‌شود تا نقطهٔ الکی روی تقویم نگذارد و روز را الکی جزو streak حساب نکند.

**حال‌وهوا (Mood)** — پنج درجه از «خیلی بد» تا «عالی». رنگ حال‌وهوا لهجهٔ کارت و رنگ خانهٔ تقویم است، پس یک ماه تقویم قبل از خواندن حتی یک کلمه به‌صورت نقشهٔ حال‌وهوا خوانده می‌شود.

**عکس** — یک عکس برای هر خاطره، از طریق Photo Picker (بدون هیچ مجوز حافظه‌ای). فایل داخل حافظهٔ خصوصی اپ کپی می‌شود؛ نگه‌داشتن خودِ `content://` گالری بی‌فایده است چون دسترسی‌اش با ریبوت از بین می‌رود.

**همین روز، سال‌های قبل** — خاطره‌های همان روزِ **شمسی** در سال‌های گذشته. سالی که آن روز را ندارد (۳۰ اسفند در سال غیرکبیسه) رد می‌شود، نه اینکه روی ۲۹ بلغزد.

**تولدها** — تب اختصاصی: افراد، شمارش معکوس، سن، ۵۰ پیام تبریک آماده، ایده‌های کادو (که به یادداشت تبدیل می‌شوند) و یادآوری چند روز قبل.

**یادداشت** — دفترچه‌های رنگی با جلد و ایموجی، سنجاق کردن، رنگ اختصاصی.

**تقویم شمسی** — ماه واقعی جلالی؛ روزهای نوشته‌شده با رنگ حال‌وهوا تینت می‌شوند و روزهای عکس‌دار نقطهٔ دوم می‌گیرند.

**پوسته‌های رنگی** — ۶ پوسته با نسخهٔ روشن و تیره.

**جست‌وجو و فیلتر** — روی عنوان، متن و برچسب؛ فیلتر «دلخواه‌ها» و «عکس‌دار».

## ۵. معماری

```
data/       local (Room)، prefs (DataStore)، repo، backup (JSON)
core/       date (تقویم جلالی + فرمترها)، util (اعداد فارسی)
notifications/  AlarmManager + Receiver + WorkManager (فقط تولدها)
ui/         theme، components، diary، calendar، birthday، notes، profile، onboarding، search
navigation/ مقصدهای Bottom Navigation
```

- **MVVM** با `ViewModel` + `StateFlow`؛ بدون فریم‌ورک DI (سرویس‌لوکیتور سبک در `DiaryApp`).
- منبع حقیقت واحد برای هر حوزه: `DiaryRepository` (خاطرات + فایل عکس‌ها)، `NoteRepository`، `BirthdayRepository` (شامل زمان‌بندی آلارم، تا فرد و یادآوری‌اش هرگز ناهماهنگ نشوند).

### دیتابیس (Room v1)

`DiaryEntity`: id, **date (یکتا)**, title, body, mood, tags, photoUri, favorite, createdAt, updatedAt
`NoteEntity` / `NotebookEntity`، `BirthdayPersonEntity` / `GiftIdeaEntity`

نسخه از **۱** شروع می‌شود: این اپ هنوز منتشر نشده، پس هیچ دیتابیس نصب‌شده‌ای برای مهاجرت وجود ندارد. جدول‌های Task/Category که «روزی» داشت اصلاً ساخته نمی‌شوند — نگه‌داشتن جدول مرده هر نویسندهٔ مهاجرتِ بعدی را گمراه می‌کند. از این به بعد هر تغییر اسکیما به `Migration` واقعی نیاز دارد.

تاریخ‌ها به‌صورت **epochDay** ذخیره می‌شوند (تاریخ تقویمی مستقل از منطقهٔ زمانی)؛ نمایش شمسی/میلادی صرفاً لایهٔ presentation است، پس سفر بین تایم‌زون‌ها خاطره را به روز دیگری جابه‌جا نمی‌کند.

## ۶. تقویم شمسی

پیاده‌سازی واقعی الگوریتم چرخهٔ ۳۳ سالهٔ (Borkowski/خیام) در `core/date/JalaliDate.kt` — نه صرفاً ظاهر فارسیِ تقویم میلادی.

تست‌شده (`app/src/test/.../JalaliDateTest.kt`):
- رفت‌وبرگشت میلادی↔شمسی برای تمام روزهای ۱۹۵۰ تا ۲۱۰۰
- سال‌های کبیسه: ۱۳۹۵، ۱۳۹۹، ۱۴۰۳، ۱۴۰۸، ۱۴۱۲، ۱۴۱۶، ۱۴۲۰
- طول اسفند در سال کبیسه (۳۰) و عادی (۲۹)
- پیوستگی آخر اسفند → ۱ فروردین برای ۱۳۸۰ تا ۱۴۵۰
- شاخص روز هفته با مبنای شنبه = ۰

همین تقویم هم در تب «تقویم»، هم در «همین روز، سال‌های قبل» و هم در انتخاب تاریخ تولد استفاده می‌شود.

## ۷. یادآوری‌ها

تنها یادآوریِ اپ **تولد** است.

- `AlarmManager.setAlarmClock` وقتی مجاز باشد، وگرنه `setAndAllowWhileIdle` — مقاوم در برابر Doze. یک تولد باید صبحِ درست برسد، پس `USE_EXACT_ALARM` اعلام شده که هنگام نصب داده می‌شود و دیالوگ زمان اجرا ندارد.
- مجوز `POST_NOTIFICATIONS` فقط وقتی درخواست می‌شود که کاربر واقعاً یادآوری‌ای را روشن کند.
- پس از ریبوت یا آپدیت، `BootReceiver` + `RescheduleWorker` همهٔ آلارم‌ها را دوباره تنظیم می‌کنند. آلارمی که بی‌صدا ناپدید شود از نبودنش بدتر است — کاربر دقیقاً به این دلیل رویش حساب کرده که تاریخ را خودش به خاطر نمی‌آورد.
- کارت «عیب‌یابی اعلان» در پروفایل وضعیت مجوز، مجاز بودن آلارم دقیق و راهنمای محدودیت باتری را نشان می‌دهد و دکمهٔ تست دارد.

## ۸. پشتیبان‌گیری

خروجی/ورودی JSON نسخه‌دار از طریق Storage Access Framework (بدون نیاز به مجوز فایل). فرمت `diary-backup` v1 عمداً transport-agnostic است تا افزودن Cloud Backup در آینده فقط جابه‌جایی همین بایت‌ها باشد.

هر سه حوزه در فایل هستند: خاطرات، یادداشت‌ها و **تولدها**. تاریخ تولد داده‌ای است که کاربر یک‌بار وارد کرده و اگر گم شود دیگر هرگز یادآوری نمی‌شود، پس جا انداختنش بکاپ را بی‌معنی می‌کرد.

بخشی که در فایل نباشد هنگام بازیابی **دست‌نخورده می‌ماند** (پاک نمی‌شود)، تا بازیابی یک بکاپ ناقص داده‌ای را که دربارهٔ آن حرفی نزده نابود نکند.

**عکس‌ها در فایل نیستند** — بایت باینری‌اند و حجم یک بکاپ متنی را چند برابر می‌کنند. نام فایل عکس ذخیره می‌شود، پس بازیابی روی همان دستگاه عکس را هم برمی‌گرداند و روی دستگاه جدید خاطره کامل است منهای تصویر.

## ۹. کیفیت

```bash
python3 tools/verify_resources.py
python3 tools/check_callsites.py
```

این اسکریپت بررسی می‌کند: صحت XML، تطابق کامل رشته‌های فا/en و format specifierها، resolve شدن تمام `R.*`ها، **نبود متن فارسی هاردکد در کاتلین**، هشدار در صورت افزوده شدن مجوز INTERNET، سالم بودن فونت‌ها و آیکون‌ها، و تطابق دوطرفهٔ کامپوننت‌های منیفست با فایل‌های کاتلین.
