# مراحل انتشار

## نسخه‌ی فعلی — ۱.۰.۱

```kotlin
versionCode = 2        // عددی که فروشگاه می‌خواند
versionName = "1.0.1"  // چیزی که کاربر می‌بیند
```

`versionCode` همراه با نام نسخه بالا رفت. فروشگاه فایلی را که کدش را قبلاً
دیده رد می‌کند، حتی اگر نام نسخه فرق کرده باشد — پس این دو باید با هم جلو
بروند.

### قبل از آپلود

- [ ] APK امضاشده را از آخرین اجرای CI دانلود کنید
      (بخش **Artifacts** ← `roozi-release-apk`)
- [ ] در همان اجرا مطمئن شوید مرحله‌ی **Verify APK signature** سبز است —
      این تنها تضمین است که فایل با کلید انتشار امضا شده و نه با کلید دیباگ
- [ ] APK را روی یک گوشی واقعی نصب و باز کنید
- [ ] یک کار با یادآوری بسازید و منتظر بمانید تا اعلان برسد
- [ ] در تب پروفایل، پایین صفحه، شماره‌ی نسخه را ببینید

### چیزهایی که فروشگاه می‌خواهد

- [ ] فایل APK
- [ ] آیکون ۵۱۲×۵۱۲ (`store/icon-512.png`)
- [ ] متن‌ها از `store/listing-fa.md`
- [ ] **اسکرین‌شات** — حداقل ۳ تا، از گوشی خودتان بگیرید.
      پیشنهاد: صفحه‌ی امروز با چند کار، تقویم، یادداشت‌ها، دفتر تولد، پروفایل

### درباره‌ی مجوزها

اگر فروشگاه پرسید چرا برنامه مجوز «هشدار دقیق» می‌خواهد:
یادآوری کار باید دقیقاً سر ساعتی که کاربر انتخاب کرده برسد، و بدون این مجوز
سیستم آن را تا چند دقیقه یا چند ساعت به تعویق می‌اندازد.

جدول کامل مجوزها انتهای `listing-fa.md` است.

## نسخه‌های بعدی

**مهم:** برای هر آپدیت باید `versionCode` را زیاد کنید، وگرنه فروشگاه فایل را
با پیام «نسخه تکراری» رد می‌کند.

```kotlin
versionCode = 3          // همیشه یکی بیشتر از نسخه‌ی قبل
versionName = "1.0.2"    // برای رفع اشکال جزئی
```

قاعده‌ی پیشنهادی برای `versionName`:

| نوع تغییر | مثال |
|---|---|
| رفع اشکال | `1.0.1` ← `1.0.2` |
| قابلیت جدید | `1.0.2` ← `1.1.0` |
| بازطراحی بزرگ | `1.1.0` ← `2.0.0` |

`versionCode` مستقل از این است و فقط یکی‌یکی بالا می‌رود: ۱، ۲، ۳، …

## کلید امضا — این را از دست ندهید

آپدیت‌های بعدی **فقط** با همان کلیدی پذیرفته می‌شوند که نسخه‌ی اول با آن امضا
شده. اگر کلید گم شود، دیگر نمی‌توانید همین برنامه را به‌روز کنید و باید با نام
بسته‌ی جدید از صفر منتشرش کنید — یعنی از دست دادن همه‌ی کاربران و نظرها.

از این چهار مورد جای امنی پشتیبان بگیرید:

- فایل keystore
- رمز keystore
- نام alias
- رمز key

این‌ها الان به‌عنوان سکرت در گیت‌هاب ذخیره شده‌اند
(`ROZI_RELEASE_KEYSTORE_BASE64` و سه تای دیگر)، ولی سکرت گیت‌هاب پشتیبان نیست:
قابل خواندن دوباره نیست و اگر مخزن حذف شود از بین می‌رود.
