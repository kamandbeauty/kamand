# تحلیل اپلیکیشن «حسابداری آینو» و نقشهٔ راه ساخت معادل آن (پروژهٔ کمند)

منبع بررسی:
- صفحهٔ کافه‌بازار: `cafebazaar.ir/app/com.ainoapp.aino` — نسخهٔ ۳.۱.۶، حجم ۱۳ مگابایت، ۳۳ هزار نصب، امتیاز ۴.۳ از ۵۸۳ رأی، دستهٔ امور مالی، آخرین بروزرسانی ۶ بهمن ۱۴۰۳
- سایت رسمی: `ainoapp.ir` (شرح امکانات + تعرفه‌ها)
- نسخهٔ قدیمی‌تر با پکیج `com.finance.ino` (از انتشار خارج شده) — یعنی محصول یک بار بازنویسی/مهاجرت شده است

خلاصهٔ یک‌خطی محصول: **حسابداری دوطرفه (double-entry) ساده‌شده برای اصناف، روی موبایل، ابری، چندکاربره و چندکسب‌وکاره، با درآمد اشتراکی.**

## ۱. فهرست کامل امکانات (چیزی که باید نوشته شود)

### ۱.۱ فاکتور و پیش‌فاکتور — هستهٔ محصول
| قابلیت | توضیح |
|---|---|
| پیش‌فاکتور | قابل تبدیل به فاکتور |
| فاکتور فروش | سند فروش + خروج کالا از انبار |
| فاکتور خرید | سند خرید + ورود کالا به انبار |
| برگشت از فروش | معکوس فروش |
| برگشت از خرید | معکوس خرید |
| فاکتور ضایعات | خروج کالا بدون درآمد |
| فاکتور رسمی/غیررسمی | رسمی = دارای مالیات بر ارزش افزوده و شماره‌گذاری جدا |
| محاسبهٔ سود/زیان هر فاکتور | با سه روش قیمت‌گذاری: **FIFO / LIFO / میانگین موزون** |
| پرداخت داخل فاکتور | نقدی، تراکنش بانکی، چک — به صورت جزئی یا کامل |
| وضعیت و سررسید | پرداخت‌شده / بخشی / معوق + تاریخ سررسید |
| خروجی | نمایش، چاپ، اشتراک‌گذاری به صورت PDF و عکس |
| جستجوی پیشرفته | روی لیست فاکتورها |
| تخفیف و هزینهٔ حمل | سطری و کلی (استاندارد این دسته) |

### ۱.۲ کالا و انبار
- تعریف **کالا** و **خدمت** (خدمت موجودی ندارد)
- مشخصات: موجودی اولیه، بارکد، قیمت خرید، قیمت فروش، دسته‌بندی، حداقل موجودی
- **دو واحدی**: واحد اصلی و فرعی با ضریب تبدیل (مثلاً کارتن/عدد) و نمایش موجودی بر اساس هرکدام
- کاردکس: لیست ورودی/خروجی هر کالا با جزئیات
- گزارش موجودی به صورت تعدادی و ریالی
- جستجوی پیشرفته + بارکدخوان (با دوربین)

### ۱.۳ اشخاص / طرف حساب‌ها
- مشتری، فروشنده (تأمین‌کننده)، **سهامدار** (با درصد شراکت و تسهیم سود/زیان)
- بدهکاری/بستانکاری اولیه، اطلاعات تماس، آدرس
- ثبت مستقیم بدهکاری/بستانکاری
- صورتحساب هر شخص + چاپ و اشتراک‌گذاری
- گزارش بدهکاران و بستانکاران با مانده و جمع کل

### ۱.۴ چک
- چک دریافتی و پرداختی
- چرخهٔ وضعیت: در جریان → وصول / برگشت (عودت) / خرج‌شده / باطل
- یادآوری تاریخ سررسید (نوتیفیکیشن محلی)

### ۱.۵ خزانه‌داری / بانکداری
- حساب بانکی، صندوق، تنخواه‌گردان
- دریافت، پرداخت، **انتقال بین حساب‌ها**
- لیست تراکنش‌ها + چاپ و اشتراک‌گذاری

### ۱.۶ گزارش‌ها (بخش سنگین و ارزش‌آفرین)
صورت سود و زیان · موجودی کالاها · بدهکاران و بستانکاران · **ترازنامه** · دفتر روزنامه · صورتحساب سرمایه · **تراز آزمایشی** · دفتر حساب‌ها · مرور حساب‌ها

> این فهرست یعنی زیرساخت واقعاً **دفترداری دوطرفه با کدینگ حساب‌ها** است، نه صرفاً یک فاکتورساز. هر عملیات باید سند حسابداری متوازن تولید کند.

### ۱.۷ تنظیمات و زیرساخت
- مشخصات کسب‌وکار (نام، لوگو، آدرس، شماره اقتصادی)
- تنظیمات مالی و **سال مالی** (بستن سال، انتقال مانده)
- تنظیمات فاکتور (سریال، پیش‌فرض‌ها، متن پاورقی) و تنظیمات چاپ (A4/A5/فیش ۸۰ میلی‌متری)
- قفل امنیتی برنامه (PIN/بیومتریک)
- **چندکاربره** با تعریف نامحدود کاربر و کار همزمان روی چند دستگاه ⇒ نیاز به نقش/دسترسی + همگام‌سازی
- **چندکسب‌وکاره** کاملاً مجزا ⇒ multi-tenant
- **ابری**: ذخیره و پشتیبان‌گیری روی سرور
- ثبت‌نام با **شمارهٔ موبایل** (OTP)
- پرداخت درون‌برنامه‌ای + ۱۰ روز تست رایگان

### ۱.۸ مدل درآمدی آینو (برای مقایسه)
| دوره | مبلغ (تومان) | معادل ماهانه |
|---|---|---|

## ۲. الزامات پنهانی که در فهرست فیچرها دیده نمی‌شود ولی باید نوشته شود

1. **تاریخ شمسی در همه‌جا** — ذخیره میلادی/UTC، نمایش جلالی؛ فیلترهای «امروز/این ماه/سال مالی».
2. **موتور حسابداری دوطرفه** — بدون آن ترازنامه و تراز آزمایشی درست درنمی‌آید. هر فاکتور/تراکنش ⇒ سند با ردیف‌های بدهکار/بستانکار متوازن.
3. **قیمت‌گذاری موجودی** — پیاده‌سازی FIFO/LIFO/میانگین موزون به‌ازای هر کسب‌وکار (تنظیم‌شدنی) و محاسبهٔ بهای تمام‌شدهٔ کالای فروش‌رفته.
4. **آفلاین-اول + همگام‌سازی** — کاربر مغازه‌دار وسط فروش نباید با قطعی اینترنت متوقف شود. نیاز به دیتابیس محلی، صف تغییرات، حل تعارض (LWW یا نسخه‌گذاری) و **شناسهٔ UUID سمت کلاینت** به جای auto-increment.
5. **تولید PDF/عکس فارسی راست‌به‌چپ** — فونت فارسی امبد شده، قالب فاکتور، اعداد فارسی، «به حروف» نوشتن مبلغ.
6. **چاپ حرارتی ۸۰/۵۸ میلی‌متری بلوتوثی** — نیاز اصلی فروشگاه‌ها (ESC/POS).
7. **حذف نرم (soft delete) و ردّ ممیزی (audit log)** — در نرم‌افزار مالی چندکاربره اجباری است.
8. **قفل دورهٔ مالی** — جلوگیری از ویرایش اسناد بسته‌شده.
9. **مالیات بر ارزش افزوده** و آمادگی برای **سامانهٔ مؤدیان** (آینو این را ندارد ⇒ فرصت تمایز).
10. **بکاپ/ریستور محلی** علاوه بر ابری.

## ۳. نقاط ضعف آینو = فرصت‌های کمند

از نظرات کاربران در بازار (۴.۳ کلی، ولی شکایت‌های اخیر):
- «قبل از اتمام دوره اطلاع‌رسانی نمی‌شود و **دسترسی مسدود می‌شود و کل اطلاعات مشتری از دسترس خارج می‌شود**» ⇒ **مهم‌ترین فرصت**: حالت فقط-خواندنی/خروجی گرفتن پس از انقضا. هرگز دادهٔ کاربر را گروگان نگیریم.
- «قیمت گران شده» ⇒ پلن‌بندی پلکانی، پلن رایگان محدود (مثلاً تا ۵۰ فاکتور در ماه).
- «برنامه اجرا نمی‌شود و پشتیبانی در دسترس نیست» ⇒ SLA پشتیبانی داخل اپ + پایداری.
- **وابستگی کامل به سرور** ⇒ ما آفلاین-اول باشیم.
- **نبود نسخهٔ وب/دسکتاپ** ⇒ اگر core را جدا بنویسیم، پنل وب مزیت بزرگی است (صاحب کسب‌وکار روی لپ‌تاپ، فروشنده روی موبایل).
- نبود سامانهٔ مؤدیان، نبود اتصال به کارتخوان/ترازو، نبود ورودی اکسل ⇒ همه قابل اضافه‌شدن.

## ۵. نقشهٔ راه مرحله‌ای

**فاز ۰ — پایه (۱ تا ۲ هفته)**
اسکلت پروژه، احراز هویت با OTP، مدل چند‌کسب‌وکاره، تاریخ جلالی، دیتابیس محلی، طرح‌بندی RTL.

**فاز ۱ — MVP قابل فروش (۴ تا ۶ هفته)**
اشخاص + کالا + فاکتور فروش/خرید + دریافت/پرداخت نقدی + خروجی PDF فاکتور + گزارش بدهکاران/بستانکاران و موجودی.
(همین حجم، ۸۰٪ نیاز یک مغازه‌دار را پوشش می‌دهد.)

**فاز ۲ — حسابداری واقعی (۳ تا ۴ هفته)**
کدینگ حساب، سند خودکار، دفتر روزنامه، تراز آزمایشی، ترازنامه، سود و زیان، بهای تمام‌شده با FIFO.

**فاز ۳ — خزانه و چک (۲ هفته)**
حساب/صندوق/تنخواه، انتقال، چرخهٔ چک، یادآوری سررسید.

**فاز ۴ — ابری و چندکاربره (۳ تا ۴ هفته)**
API همگام‌سازی، نقش و دسترسی، حل تعارض، بکاپ ابری.

**فاز ۵ — پول‌سازی و تمایز (۲ تا ۳ هفته)**
اشتراک و پرداخت درون‌برنامه‌ای (بازار/زرین‌پال)، حالت فقط-خواندنی پس از انقضا، چاپ حرارتی، بارکدخوان، ورودی/خروجی اکسل، پنل وب، مالیات بر ارزش افزوده.

## ۶. پیشنهاد فنی

| لایه | گزینه | چرا |
|---|---|---|
| موبایل | Flutter | یک کدبیس اندروید+iOS، RTL و فونت فارسی خوب، حجم قابل قبول (آینو ۱۳MB) |
| دیتابیس محلی | SQLite (Drift) | کوئری‌های تجمیعی گزارش‌ها روی SQL راحت است |
| بک‌اند | یکی از: Django/DRF یا NestJS + PostgreSQL | تراکنش‌های مالی، RLS برای multi-tenant |
| منطق مشترک | پکیج `core` مستقل از UI | تا بعداً وب/دسکتاپ از همان موتور استفاده کند |
| گزارش/PDF | تولید سمت کلاینت با قالب HTML→PDF | آفلاین کار می‌کند |

جایگزین سبک‌تر برای شروع سریع: Flutter + Supabase (Postgres + Auth + RLS) تا بک‌اند اختصاصی لازم نشود.

## ۷. جمع‌بندی: چه چیزی «باید» نوشته شود
اگر بخواهیم یک‌جمله‌ای بگوییم، ساختن معادل آینو یعنی نوشتن این چهار موتور، و بقیه فقط UI است:

1. **موتور سند دوطرفه** (منبع همهٔ گزارش‌ها)
2. **موتور موجودی و بهای تمام‌شده** (FIFO/LIFO/میانگین)
3. **موتور همگام‌سازی آفلاین-اول چندکاربره**
4. **موتور چاپ/PDF فارسی**

هر سه بخش دیگر (فاکتور، اشخاص، خزانه) صرفاً ورودی‌های این موتورها هستند.
